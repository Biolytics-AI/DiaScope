## Phase C — browser layout verification (Playwright, bounding-box invariants)

`demo/deck/tests/layout.spec.ts` (via `npm run test:layout -w diascope-demo-deck`,
Playwright, Chromium) asserts geometric invariants computed from real
`getBoundingClientRect()` values exposed by a `window.__diascopeDebug.layout()` hook —
not screenshot diffing. Invariants checked at every step:

- Canvas pane and narration pane never overlap.
- Pill rows stay contained within the narration pane.
- Popovers never overlap the narration pane, and never overlap their own highlighted
  target node.
- A popover stays within ~80px of its target node's rect (anchor distance check).
- Every highlighted node's rect stays inside the camera viewport (canvas rect, 4px
  tolerance).
- The detail drawer stays contained within its container and never overlaps the
  diagram pane.
- Zero browser console errors during a full run.

Each test walks the deck forward step-by-step to the end (both slide and reveal.js
fragment boundaries) re-asserting invariants at every step, then walks backward to the
start re-asserting again — a reversibility check, not just a one-directional smoke test.
Run at two viewports: **1440×900** (desktop) and **1000×700** (narrow), plus a live-resize
test (viewport changed mid-session, camera/popover re-fit correctly) and an explicit
drawer open/close test.

Results at final `HEAD`: **6/6 passing** for the default (vLLM) deck across both
viewports, **3/3 passing** per Phase B agent story (`kafka-dlq`, `oauth-pkce`) — i.e. the
suite is story-agnostic and runs unmodified against agent-authored content.

**Bugs the harness caught on its first real run** (fixed in-branch, not merely noted):

1. **Popover drift under reveal.js CSS scale.** reveal.js scales the whole slide via a
   CSS `transform: scale(...)` to fit the viewport; popover positioning code that read
   `offsetWidth`/`offsetLeft` (unscaled, layout-space values) instead of
   `getBoundingClientRect()` (scaled, viewport-space values) drifted from its target as
   soon as the deck was scaled below 1:1. Fixed by switching popover geometry to
   `getBoundingClientRect()` throughout.
2. **Edge tooltip `position: fixed` under a transformed ancestor.** CSS `position: fixed`
   is documented to escape a transformed ancestor's containing block and position
   relative to the viewport instead — which broke under reveal.js's slide-level
   `transform: scale`. The edge-hover tooltip was positioning against the wrong frame of
   reference as a result.
3. **~40px camera/popover offset from D2's nested inner-`<svg>` viewBox.** D2's compiled
   SVG output nests an inner `<svg>` with its own non-zero-origin `viewBox` (observed
   `-89,-89,...`); code that assumed the outer and inner SVG shared a coordinate origin
   was off by a constant ~40px in both camera fit and popover placement. Fixed via an
   explicit content-transform correction in `camera.ts` that accounts for the inner
   viewBox origin.

## Phase D — design-quality audit (`/audit`, `/animate`, `/polish`)

Full UI audit (two-pane scene, popovers, pills, drawer, tooltips, desktop + narrow) found
**21 findings**: 2 Critical, 5 High, 9 Medium, 5 Low.

**Fix round 1** (10 items): reveal.js theme CSS reset (stop leaking reveal's default
theme styles into DiaScope's own components), drawer typography/relocation/focus
management, ghost pill styling + visible focus rings, collapsed to a single navigation
system (removed a redundant/conflicting nav affordance), canvas framing fixes, overview
camera fit correction, keyboard access to nodes (not just mouse/click), design
token/border-radius unification across components, a proper title slide, and a CSS
container query for responsive pane sizing.

**Re-audit:** verdict `ITERATE` — 4 items remained.

**Fix round 2** (4 items): narration pane text sizing, a drawer/popover simultaneous-open
conflict (both could be open and overlapping at once), edge-trace fade timing, and
enlarged interactive hit areas.

**Final re-audit:** verdict `CLEAN`.

defects the automated checks caught, not findings invented after the fact:

   `offsetWidth`/`offsetLeft` instead of `getBoundingClientRect()`). — Phase C, fixed.
2. Edge-hover tooltip `position: fixed` escaping the transformed slide ancestor and
   positioning against the wrong frame of reference. — Phase C, fixed.
3. ~40px camera/popover offset caused by D2's nested inner-`<svg>` non-zero-origin
   `viewBox` (`-89,-89,...`) not being accounted for; fixed via a content-transform
   correction in `camera.ts`. — Phase C, fixed.
4. 21 design-quality findings (2 Critical / 5 High / 9 Medium / 5 Low) spanning theme

   inconsistency — fixed across two rounds, verified clean on re-audit. — Phase D, fixed.

## Deferred items (documented, not fixed in M1)

- **Edge-tooltip keyboard access** (WCAG 1.4.13 — content shown on hover/focus must also
  be dismissible/hoverable/persistent by keyboard-only users). Edge tooltips currently
  fire on mouse hover only; no keyboard-equivalent path exists yet.
- **Full wide-diagram strategy.** No dedicated layout strategy yet for diagrams
  significantly wider than the canvas pane beyond the existing camera fit/pan/zoom;
  needs a deliberate design pass.
- **Layout suite not wired into CI.** `npm run test:layout -w diascope-demo-deck` is
  verified locally in this milestone but is not yet a CI gate — it needs a
  webServer-in-CI setup (Playwright's `webServer` config already handles local
  `reuseExistingServer`, but CI needs its own headless boot).
- **`graph render` CLI verb** (visual PNG/SVG preview of a resolved step without a
  browser) — requested by both Phase B subagents, out of scope for M1's text/JSON-only
  CLI surface, proposed for the next milestone.
